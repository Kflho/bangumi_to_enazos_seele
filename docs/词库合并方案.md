# 词库合并方案

多用户、多日期的词库导出之后，迟早要把它们并成一个题库。这份文档先定规则，
等真要用时按这里实现。

> 现状：数据层合并已经实现在 `merge_bank.py`（按 subject id 对齐、别名并集、
> 评论并列成多条提示）。纯文本合并、歧义别名开关还没做。

## 场景

手里会有三类文件：

| 来源 | 例子 | 特点 |
|---|---|---|
| 同一天、多个用户 | `723737-2026-10-20.txt`、`kflhotat-2026-10-20.txt` | 同一作品可能被多人标记，别名互补 |
| 同一用户、多个日期 | `kflhotat-2026-10-20.txt`、`kflhotat-2026-11-05.txt` | 新的是旧的超集，可能有改名、改备注 |
| 外部题库 | 别人给的 txt | 没有 id，只能按标题匹配 |

前两类是我们自己导出的，能拿到 subject id；第三类拿不到。所以合并分两条路。

## 首选：在数据层合并，不碰文本

既然收藏快照（`bin/data/collections/<user>-tN.json`）和条目缓存
（`bin/data/subjects/<id>.json`）都在本地，合并最稳的做法是**导出时直接合并多用户**，
一条文本解析都不用写：

```bash
python bangumi_to_enazo.py --user 723737 --user kflhotat --merge \
    --out bin/exports/merged-2026-10-20.txt
```

好处：

- 同一个作品按 subject id 天然对齐，不会因为标题写法不同漏合并；
- 别名并集直接用缓存里的原文，不用从文本里反向解析；
- 小狐狸提示取自各自的收藏吐槽，来源可追溯。

代价：合并结果和单人导出走的是同一套拼行逻辑，任何清洗规则改动都会同时影响两边。

## 备选：文本层合并

只有对方给的 txt、或者要合历史归档时才用。流程是「解析 → 归一化 → 合并 → 重新拼行」。

### 解析

一行拆成三段：

```text
词条名,别名一,别名二$小狐狸提示
  └ 词条名   └ 别名列表（按 , 切）   └ 提示（$ 之后原样）
```

注意：词条名里已被清洗成 `-`，不会再有分隔符；`$` 之后不再切分。

### 归一化（只用于匹配，输出仍用原样）

1. 全角转半角（`Ａ` → `A`、`１` → `1`）；
2. 英文统一小写；
3. 去掉所有空白；
4. 去掉常见标点（`・:：!！?？。.、,，` 和括号）；
5. 括号里的季数保留，例如 `第三季`、`2nd Season` 不剥。

归一化后的键用于判定「是不是同一个词条」。**只在合并过程中使用，写回题库时用原始写法。**

### 合并规则

| 字段 | 规则 | 冲突时 |
|---|---|---|
| 词条名 | 取第一个来源的写法 | 归一化后相同但写法不同，记进报告，人工挑 |
| 别名 | 取并集，按来源顺序追加 | 完全相同（忽略大小写）的丢弃，不重复输出 |
| 小狐狸提示 | 默认取最长的一条 | `--hint first` 取第一个、`--hint join` 用 `；` 拼接、`--hint none` 全部丢弃 |
| 顺序 | 按来源顺序，先出现的在前 | 想要固定顺序用 `--sort title` 按归一化标题排 |

### 别名冲突

同一个别名挂到两个不同条目上（比如 `Fate` 既是某条目的别名，又是另一个条目的开头），
enazo 猜题时会出现两个候选。处理：

- 默认保留，但写进报告的「歧义别名」一节；
- `--drop-ambiguous` 把这些别名从所有条目里删掉，牺牲命中率换确定性；
- 太短的别名（长度 ≤ 2）默认也列进报告，方便人工判断要不要删。

## 输出

```text
bin/exports/merged-2026-10-20.txt
bin/exports/report-merged-2026-10-20.md
```

报告至少要写清楚：

- 输入文件列表、各自词条数；
- 合并后词条数、别名总数、平均每行别名数；
- 被合并掉的重复词条数（按来源列）；
- 词条名写法冲突（同 id 不同名）；
- 歧义别名（一对多）；
- 提示取舍结果（谁被丢掉）。

## 边界情况

**同一作品的不同季**：subject id 不同，就是两个词条，不合并。别名里带季数的
（`第三季`、`3rd Season`）保留，别互相吸收。

**改名或换译名**：同 id 不同 `name`，报告里列出来，默认取第一个来源的写法。

**已删除的条目**：收藏里还在、接口 404，没有 `name_cn`，别名只有导出表自带的那一个。
合并时按 id 对齐即可。

**外部题库没有 id**：只能按归一化标题匹配。同名不同作品（重名动画）会误合并，
报告里标出「按标题合并」的条目，人工抽查。

**重复行**：自己导出的文件里理论上不会有，但历史归档可能有，合并时按归一化键去重。

## 实施顺序

1. ~~**第一步**：数据层合并，按 subject id 对齐~~ —— 已实现，`merge_bank.py`
   直接吃收藏快照和条目缓存，产出合并题库与报告；
2. **第二步**：给导出加 `--merge`，一条命令直接出合并结果，省掉单独跑一次；
3. **第三步**：加纯文本模式，只按归一化标题匹配，覆盖外部题库；
4. **第四步**：加冲突报告与 `--drop-ambiguous`。

## 验收

- 合并前后总词条数 = 各来源去重后的并集，不多不少；
- 同一 id 的词条只出现一次；
- 输出里没有残留的分隔符和空词条名；
- 报告里的冲突条目能对应到具体来源文件；
- `--check` 对合并结果同样通过。
